** Garbage Collection and IGC

We run on the IGC (incremental garbage collector) branch. Crank GC
thresholds sky-high during init, then reset.

The =gc-cons-*= pair is the fallback for a non-IGC build — an MPS
build collects incrementally and ignores it. The only tuning knob
the igc branch actually exposes is =igc-step-interval=: how many
seconds of GC work MPS may do when Emacs is idle (default 0 = do
nothing when idle). Letting it reclaim a little during idle keeps
pauses from piling up mid-edit. It is unbound on a stock build, so
guard with =boundp= instead of defining a stray variable.

No =focus-out= GC hook: =focus-out-hook= was made obsolete in Emacs
27.1 and removed in 28, so it never fired (=after-focus-change-function=
is the modern equivalent), and forcing a full stop-the-world
=garbage-collect= is exactly what an incremental collector exists to
avoid.

#+begin_src emacs-lisp
  (setq gc-cons-threshold most-positive-fixnum
        gc-cons-percentage 0.6)

  (add-hook 'emacs-startup-hook
            (lambda ()
              (setq gc-cons-threshold (* 16 1024 1024)
                    gc-cons-percentage 0.1)))

  ;; IGC tuning — `igc-step-interval' is the branch's only knob.
  (when (boundp 'igc-step-interval)
    (setq igc-step-interval 0.1))
#+end_src

** File Name Handler Cache

Borrowed from [[https://github.com/jamescherti/minimal-emacs.d][minimal-emacs.d]]. Every =load= and =require= during
startup consults =file-name-handler-alist= (TRAMP, jka-compr, …),
none of which is needed to load our own config. Empty it during
init, then restore the original value — merged with anything added
in the meantime — once startup finishes. The =jka-compr= handler is
kept when the loaddefs are gzipped (the case on Nix, where lisp
sources ship as =.el.gz=).

#+begin_src emacs-lisp
  (defvar my--file-name-handler-alist
    (default-toplevel-value 'file-name-handler-alist))

  (unless noninteractive
    (set-default-toplevel-value
     'file-name-handler-alist
     (if (locate-file-internal "calc-loaddefs.el" load-path)
         nil
       (list (rassq 'jka-compr-handler my--file-name-handler-alist))))
    (add-hook 'emacs-startup-hook
              (lambda ()
                (set-default-toplevel-value
                 'file-name-handler-alist
                 (delete-dups (append file-name-handler-alist
                                      my--file-name-handler-alist))))
              101))
#+end_src

** Startup Redisplay and Mode Line

Also from minimal-emacs.d: suppress redisplay, echo-area messages,
and the mode line while init runs, so Emacs paints the frame once
instead of dozens of times. Everything is restored on the first
=post-command-hook= firing, with =emacs-startup-hook= as a safety
net in case init errors out.

#+begin_src emacs-lisp
  (unless noninteractive
    ;; Hide the mode line until init installs the real one.
    (put 'mode-line-format 'initial-value
         (default-toplevel-value 'mode-line-format))
    (setq-default mode-line-format nil)

    (setq-default inhibit-redisplay t
                  inhibit-message t)

    (defun my--reset-inhibited-vars ()
      "Restore redisplay, messages, and the mode line after startup."
      (setq-default inhibit-redisplay nil
                    inhibit-message nil)
      (unless (default-toplevel-value 'mode-line-format)
        (setq-default mode-line-format
                      (get 'mode-line-format 'initial-value)))
      (remove-hook 'post-command-hook #'my--reset-inhibited-vars))

    (add-hook 'post-command-hook #'my--reset-inhibited-vars -100)
    (add-hook 'emacs-startup-hook #'my--reset-inhibited-vars 101))
#+end_src

** Process I/O

Read subprocess output in much larger chunks. The main beneficiary
is Eglot: LSP servers send responses far bigger than the 4 kB
default, and adaptive buffering only helps processes that trickle
output.

1 MiB, not more: Emacs enlarges the subprocess pipe to this value
with =F_SETPIPE_SZ=, and Linux caps unprivileged pipes at
=fs.pipe-max-size= (1 MiB by default). Asking for 4 MiB makes the
=fcntl= fail silently and leaves the pipe at the 64 kB default —
the bigger value defeats itself.

#+begin_src emacs-lisp
  (setq read-process-output-max (* 1024 1024))
  (setq process-adaptive-read-buffering nil)
#+end_src

** Bootstrap

Nix provides all packages on the load-path already. We just need
=use-package= (built-in since Emacs 29) and tell it never to install
anything.

=package-initialize= is load-bearing, despite =package.el= having no
archives to talk to. =early-init.el= sets =package-enable-at-startup= to
nil, which stops Emacs from running =package-activate-all= on its own, so
this call is the only thing that activates the packages Nix put under
=site-lisp/elpa/= and loads their =*-autoloads.el=. Drop it and every
autoloaded symbol goes void — =global-corfu-mode=, =popper-mode=,
=diff-hl-margin-mode= and friends all fail at =:init= / =:config= time.

#+begin_src emacs-lisp
  (setq package-archives nil)
  (setq package-enable-at-startup nil)

  (require 'package)
  ;; Activates Nix-provided packages and loads their autoloads.
  ;; Required: package-enable-at-startup is nil, so nothing else does this.
  (package-initialize)
  (require 'use-package)
  (setq use-package-always-ensure nil)
#+end_src

** Literate Config

=README.org= is the source of truth; =init.el= and =early-init.el= are
generated from it. Two conveniences keep live editing painless:

- =C-c C-c= on a source block evaluates it immediately — no tangle, no
  restart. =C-c '= opens the block in a real =emacs-lisp-mode= buffer
  where =C-M-x= and =C-x C-e= behave exactly as in a =.el= file.
- Saving this file re-tangles it, so the generated =.el= files can never
  drift from the prose.

Note the literal =~/.emacs.d/=: =user-emacs-directory= is redirected to
=var/= in =early-init.el=, so it is the wrong thing to build this path
from.

#+begin_src emacs-lisp
  (defvar my/literate-config-file
    (expand-file-name "README.org" "~/.emacs.d/")
    "The org file this configuration is tangled from.")

  (defun my/literate-config-buffer-p ()
    "Return non-nil if the current buffer visits `my/literate-config-file'."
    (and buffer-file-name
         (file-equal-p buffer-file-name my/literate-config-file)))

  (defun my/org-babel-tangle-config ()
    "Tangle the literate config when it is saved."
    (when (my/literate-config-buffer-p)
      (let ((org-confirm-babel-evaluate nil))
        (org-babel-tangle)
        (message "Tangled %s" (file-name-nondirectory my/literate-config-file)))))

  (add-hook 'org-mode-hook
            (lambda ()
              (add-hook 'after-save-hook #'my/org-babel-tangle-config nil t)))
#+end_src

** Mode Line

Count Flymake diagnostics by *severity*, not by literal type:
Eglot reports its diagnostics as =eglot-error= / =eglot-warning= /
=eglot-note=, so matching on =:error= / =:warning= counted zero in
every LSP-managed buffer and the mode line showed a green ✓ next to
actual errors. =flymake--severity= resolves any type through its
=flymake-category=, which covers both built-in backends and Eglot.

No caching layer: =flymake-after-diagnostics-hook= does not exist
(the =add-hook= calls silently did nothing, the cache never
updated), and none is needed — the =:eval= runs on redisplay, which
is also exactly when a stale count would otherwise linger.

#+begin_src emacs-lisp
  (defun my/ml-flymake ()
    "Flymake error/warning counts for the mode-line, by severity."
    (when (bound-and-true-p flymake-mode)
      (let ((err-level (warning-numeric-level :error))
            (warn-level (warning-numeric-level :warning))
            (errors 0)
            (warnings 0))
        (dolist (d (flymake-diagnostics))
          (let ((sev (flymake--severity (flymake-diagnostic-type d))))
            (cond ((>= sev err-level)  (setq errors (1+ errors)))
                  ((>= sev warn-level) (setq warnings (1+ warnings))))))
        (concat
         (when (> errors 0)
           (propertize (format " !%d" errors) 'face '(:foreground "#e57373")))
         (when (> warnings 0)
           (propertize (format " ⚠%d" warnings) 'face '(:foreground "#ffb74d")))
         (when (= (+ errors warnings) 0)
           (propertize " ✓" 'face '(:foreground "#81c784")))))))

  (setq-default mode-line-format
  			  '(" "
  				(:eval (if (buffer-modified-p)
  						   (propertize "●" 'face '(:foreground "#ffb74d"))
  						 " "))
  				" %b "
  				"%l:%C  "
  				(:eval (my/ml-flymake))
  				"  "
  				mode-line-end-spaces))

** Eglot (LSP)

Eglot is started manually (=M-x eglot=), not from =prog-mode-hook= — a
server is only worth spawning once you actually want one.

The event log is off: =eglot-events-buffer-size= was made obsolete in
Eglot 1.16 (Emacs 30) and replaced by the plist
=eglot-events-buffer-config=, so setting the old name now only earns a
warning and logs everything anyway.  =:size 0= disables the log; raise
it to a few thousand when a server misbehaves and =M-x eglot-events-buffer=
has to show the traffic. Even with the buffer off, the default
=jsonrpc--log-event= still serializes every JSON-RPC payload into it, so
=jsonrpc-event-hook= is emptied too — the tradeoff is that bumping the size
later for debugging buys you nothing until the hook is restored.

Performance tuning from [[https://www.jamescherti.com/emacs-eglot-performance/][Configuring Emacs Eglot for Optimal Performance]]:

- =eglot-max-file-watches= caps OS file descriptors consumed watching the
  tree (a =defvar=, global across all servers; default 10000).
- =eglot-code-action-indications= is emptied so Eglot stops polling the
  server for available code actions on idle — no lightbulb/margin/eldoc
  hint, but =M-x eglot-code-actions= still works.
- =eglot-ignored-server-capabilities= grows beyond the formatting pair:
  nothing here uses LSP folding or on-type formatting, and inlay hints,
  symbol highlighting, code lenses, document links and color swatches are
  all dropped for responsiveness. Each one is a deliberate feature loss.

=eglot-ignored-server-capabilities= is read at request time by
=eglot-server-capable= with dynamic scope, so it can be re-enabled
per-buffer (e.g. =setq-local= in a mode hook before the server connects).
=:colorProvider= is an exception: Eglot 1.23 has no client-side
implementation of document colors, so the symbol is inert either way — it
is listed here for intent and future-proofing only.

** Snippets (Tempel)

Using Tempel instead of yasnippet — lighter, uses the same template
file as =var/templates=.

Two different Capfs, on purpose:

- Non-Eglot buffers (prog/text/org) get =tempel-complete=, which lists
  templates in the popup so they stay discoverable.
- Eglot-managed buffers get =tempel-expand=, which fires only on an exact
  template name. =tempel-complete= is unusable there: when the text at
  point matches no template, =tempel--prefix-bounds= falls back to
  =bounds-of-thing-at-point=, so it returns *every* template at nearly
  any symbol and buries the LSP candidates.

=M-+= (=tempel-complete=) and =M-*= (=tempel-insert=) browse templates on
demand anywhere, including Eglot buffers.

Newer Tempel has dropped =tempel-trigger-prefix= in favour of the prefix
heuristic above; the setting below is inert on those versions and still
gates on an older pin.

    "Move to first non-whitespace char, or column 0 if already there."
    (interactive "^p")

    (when (/= arg 1)
      (let ((line-move-visual nil))

      (open-line 1)
      (forward-line 1)
      (yank)

** Surround

=surround.el= covers what =vim-surround= did, without a modal layer.
=M-'= is a prefix, so the package is only loaded the first time it is
pressed (=:bind-keymap= autoloads on the prefix).

| Keys        | Action                                        |
|-------------+-----------------------------------------------|
| =M-' s (=   | surround region/symbol with =(= … =)=         |
| =M-' d (=   | delete the surrounding =(= … =)=              |
| =M-' c ( [= | change surrounding =(= … =)= to =[= … =]=     |
| =M-' i (=   | mark inside the pair                          |
| =M-' o (=   | mark the pair including the delimiters        |
| =M-' k (=   | kill inside the pair                          |
| =M-' K (=   | kill the pair including the delimiters        |

Any of the pair characters work on either side, so =M-' d )= is the
same as =M-' d (=. Quotes, backticks and =*= / =_= are pairs too.

=M-'= is =abbrev-prefix-mark= by default; this shadows it. As with
every other package here, =surround= has to come from Nix — add
=epkgs.surround= to the home-manager =emacs= package list, or the
=:bind-keymap= will fail to autoload.

#+begin_src emacs-lisp
  (use-package surround
    :ensure nil
    :bind-keymap ("M-'" . surround-keymap))

* LLM (GPTel)
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

One backend: *DeepSeek*, straight at =api.deepseek.com=, with the key
read from =~/.authinfo.gpg=. Its API is OpenAI-compatible, so nothing
sits in between — no OpenRouter account, no LiteLLM proxy to keep
running, no second key store to keep in sync.

Two models are served there: =deepseek-chat= for everything, and
=deepseek-reasoner= for the problems worth waiting on.

** Backend and API Key
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

#+begin_src emacs-lisp
  (require 'auth-source)

  (defvar my-gptel--key-cache nil
    "DeepSeek API key entered by hand this session, if any.")

  (defun my-gptel-key ()
    "Return the DeepSeek API key.
  Search `auth-sources' for api.deepseek.com first, then the
  DEEPSEEK_API_KEY environment variable, and only then prompt — caching
  the answer for the session."
    (or (auth-source-pick-first-password :host "api.deepseek.com"
                                         :user "apikey")
        (getenv "DEEPSEEK_API_KEY")
        my-gptel--key-cache
        (setq my-gptel--key-cache (read-passwd "DeepSeek API key: "))))

  (defvar my-gptel-models '(deepseek-chat deepseek-reasoner)
    "Models offered by the DeepSeek backend.
  Run `my-gptel-refresh-models' to replace this with whatever the API
  currently advertises.")

  (defvar my-gptel-deepseek nil
    "The DeepSeek gptel backend.")

  (use-package gptel
    :ensure nil
    :config
    (setq gptel-default-mode 'org-mode)
    (setq gptel-track-media t)

    ;; `gptel-make-deepseek' knows about `deepseek-reasoner''s separate
    ;; reasoning_content field, so prefer it; on an older Nix pin that
    ;; lacks it the plain OpenAI constructor talks to the same endpoint.
    (setq my-gptel-deepseek
          (if (fboundp 'gptel-make-deepseek)
              (gptel-make-deepseek "DeepSeek"
                :stream t
                :key #'my-gptel-key
                :models my-gptel-models)
            (gptel-make-openai "DeepSeek"
              :host "api.deepseek.com"
              :endpoint "/chat/completions"
              :stream t
              :key #'my-gptel-key
              :models my-gptel-models)))

    (setq gptel-backend my-gptel-deepseek)
    (setq gptel-model 'deepseek-chat)

    :bind
    (("C-c g g" . gptel)
     ("C-c g s" . gptel-send)
     ("C-c g m" . gptel-menu)
     ("C-c g a" . gptel-add)
     ("C-c g f" . gptel-add-file)
     ("C-c g r" . gptel-rewrite)
     ("C-c g k" . gptel-abort)))

  (defun my-gptel-refresh-models ()
    "Sync the backend's model list with what DeepSeek advertises.
  Doubles as a health check: an error here means the key is wrong, the
  account is out of credit, or the network is down."
    (interactive)
    (let* ((key (my-gptel-key))
           (url-request-extra-headers
            (list (cons "Authorization" (concat "Bearer " key))))
           (buf (url-retrieve-synchronously "https://api.deepseek.com/models"
                                            t nil 30)))
      (unless buf
        (user-error "No response from api.deepseek.com"))
      (unwind-protect
          (with-current-buffer buf
            (goto-char (point-min))
            (unless (search-forward "\n\n" nil t)
              (user-error "Malformed response from api.deepseek.com"))
            (let* ((payload (json-parse-buffer :object-type 'plist
                                               :array-type 'list))
                   (models (mapcar (lambda (m) (intern (plist-get m :id)))
                                   (plist-get payload :data))))
              (unless models
                (user-error "No models listed by api.deepseek.com"))
              (setq my-gptel-models models)
              (setf (gptel-backend-models my-gptel-deepseek) models)
              (message "DeepSeek: %s"
                       (mapconcat #'symbol-name models ", "))))
        (kill-buffer buf))))

*** The API key

No key is stored in this repo. =my-gptel-key= looks in three places,
in order:

1. =~/.authinfo.gpg= — the preferred spot, the same file Gnus already
   uses:
   #+begin_src authinfo
     machine api.deepseek.com login apikey password sk-xxxxxxxx
   #+end_src
2. the =DEEPSEEK_API_KEY= environment variable, for a key injected by
   home-manager or sops;
3. a =read-passwd= prompt, cached for the session.

Note the =login apikey= field — that is the user name gptel's own
auth-source helper expects, so the same line keeps working if this
function is ever dropped in favour of =gptel-api-key-from-auth-source=.

The key is looked up lazily, at the first request: =:key= is the
function itself, not its result, so a locked =authinfo.gpg= is only
decrypted when you actually send something, and a rotated key is picked
up by restarting Emacs rather than editing anything here.

*** Models

| Model                | What it is                                             |
|----------------------+--------------------------------------------------------|
| ~deepseek-chat~      | The default. Fast, cheap, tool-capable.                 |
| ~deepseek-reasoner~  | Thinks first, answers second — slower, for hard bugs.    |

=M-x my-gptel-refresh-models= replaces that list with whatever the API
advertises today and doubles as a health check on the key. Nothing
needs restarting; the model picker in =C-c g m= updates in place.

*** Switching models

=C-c g m= opens the transient menu, where the model can be changed
globally, buffer-locally, or for the next request only. The presets
below are the fast path: =@code= for work in a project, =@reason= when
=deepseek-chat= has already got it wrong twice.

** Project Context
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

Four layers, cheapest first. The point is that the model should
*fetch* what it needs rather than have the whole repo pasted at it —
tokens are billed per request, and a stuffed context makes answers
worse, not better.

1. *A chat buffer per project.* =C-c g p= opens =*gptel: NAME*= with
   =default-directory= at the project root, so every tool call runs
   there. It plays well with tabspaces: the buffer belongs to the tab
   its project lives in.
2. *An instruction file.* On first open, the project root is searched
   for =AGENTS.md=, =.gptel.md=, =CLAUDE.md= or =CONVENTIONS.md=; the
   first hit is appended to =my-gptel-code-directive= and set as that
   buffer's system message. This is the knob to turn per repo — build
   commands, house style, "don't touch the generated files".
   =C-c g R= re-reads it after an edit.
3. *Fast context adding.* =C-c g P= completes over =project-files= and
   hands the result to =gptel-add-file=, instead of navigating dired.
   Gitignored files stay out, because
   =gptel-context-restrict-to-project-files= defaults to =t=.
4. *Tools.* =search_project=, =list_project_files= and =read_file= let
   the model pull exactly the lines it needs. See the tools section.

#+begin_src emacs-lisp
  (defvar my-gptel-code-directive
    "You are a programming assistant working inside Emacs on the user's project.
  Read the project with your tools instead of guessing: list files, search,
  and read what you need before answering.  Keep answers short, show real
  code, and say plainly when you are unsure."
    "Base system message for project chats and the `code' preset.")

  (defvar my-gptel-project-instruction-files
    '("AGENTS.md" ".gptel.md" "CLAUDE.md" "CONVENTIONS.md")
    "File names looked for at a project root, in order of preference.
  The first one that exists is appended to `my-gptel-code-directive' to
  form the system message of that project's chat buffer.")

  (defun my-gptel-project-root (&optional dir)
    "Return the project root for DIR, or nil when there is no project."
    (let ((default-directory (or dir default-directory)))
      (when-let ((pr (project-current)))
        (project-root pr))))

  (defun my-gptel-project-instructions (root)
    "Return (FILE . TEXT) for ROOT's instruction file, or nil if it has none."
    (when root
      (when-let ((file (seq-some (lambda (name)
                                   (let ((f (expand-file-name name root)))
                                     (and (file-readable-p f) f)))
                                 my-gptel-project-instruction-files)))
        (with-temp-buffer
          (insert-file-contents file)
          (cons file (buffer-string))))))

  (defun my-gptel-project-system-message (root)
    "Build the system message for the project at ROOT."
    (let ((instructions (my-gptel-project-instructions root)))
      (concat my-gptel-code-directive
              (format "\n\nProject root: %s"
                      (abbreviate-file-name (or root default-directory)))
              (when instructions
                (format "\n\nProject instructions from %s:\n\n%s"
                        (file-name-nondirectory (car instructions))
                        (cdr instructions))))))

  (defun my-gptel-set-system-message (text)
    "Set TEXT as the system message of the current buffer.
  `gptel-system-prompt' was called `gptel--system-message' before gptel
  0.9.9.6, so honour both — the Nix pin decides which one exists."
    (if (boundp 'gptel-system-prompt)
        (setq-local gptel-system-prompt text)
      (setq-local gptel--system-message text)))

  (defun my-gptel-project-reload ()
    "Re-read the project instruction file into this buffer's system message."
    (interactive)
    (let* ((root (my-gptel-project-root))
           (instructions (my-gptel-project-instructions root)))
      (my-gptel-set-system-message (my-gptel-project-system-message root))
      (message "gptel: context reloaded for %s%s"
               (abbreviate-file-name (or root default-directory))
               (if instructions
                   (format " (%s)" (file-name-nondirectory (car instructions)))
                 " (no instruction file)"))))

  (defun my-gptel-project ()
    "Open a gptel chat buffer dedicated to the current project.
  The buffer's `default-directory' is the project root — so tools run
  there — and its system message carries the project's instruction file
  if it has one.  Reuses the buffer on subsequent calls."
    (interactive)
    (let* ((pr (project-current))
           (root (if pr (project-root pr) default-directory))
           (name (if pr (project-name pr) "default"))
           (buf-name (format "*gptel: %s*" name))
           (fresh (not (get-buffer buf-name)))
           (buf (gptel buf-name)))
      (with-current-buffer buf
        (setq default-directory root)
        (when fresh (my-gptel-project-reload)))
      (pop-to-buffer buf)))

  (defun my-gptel-add-project-file (file)
    "Add FILE, completed from the current project's files, to gptel's context."
    (interactive
     (let ((pr (or (project-current)
                   (user-error "Not inside a project"))))
       (list (completing-read "Add to gptel context: "
                              (project-files pr) nil t))))
    (gptel-add-file file))
#+end_src

Context added with =C-c g a= / =C-c g f= / =C-c g P= is *live*: files
and regions are re-read at each request, not snapshotted when added.
=C-c g m= → /inspect context/ shows what is currently attached, which
is worth a glance before an expensive request.

** GPTel Tools
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

Tools extend gptel so the LLM can take actions inside Emacs or read
external data during a conversation.  All tools here are registered
after gptel loads.  =deepseek-chat= supports tool calls;
=deepseek-reasoner= has historically refused them, which is why the
=reason= preset below ships without any — check DeepSeek's API docs
before assuming otherwise.

#+begin_src emacs-lisp
  (with-eval-after-load 'gptel

    (setq gptel-use-tools t)

    ;; Read buffer contents
    (gptel-make-tool
     :name "read_buffer"
     :function (lambda (buffer)
                 (unless (buffer-live-p (get-buffer buffer))
  				 (error "Error: buffer %s is not live." buffer))
                 (with-current-buffer buffer
  				 (buffer-substring-no-properties (point-min) (point-max))))
     :description "Return the contents of an Emacs buffer"
     :args (list '(:name "buffer"
  					   :type string
  					   :description "The name of the buffer whose contents are to be retrieved"))
     :category "emacs")

    ;; Read file contents
    (gptel-make-tool
     :name "read_file"
     :function (lambda (filepath)
                 (with-temp-buffer
  				 (insert-file-contents (expand-file-name filepath))
  				 (buffer-string)))
     :description "Read and return the contents of a file"
     :args (list '(:name "filepath"
  					   :type string
  					   :description "Path to the file to read. Supports relative paths and ~."))
     :category "filesystem")

    ;; List directory contents
    (gptel-make-tool
     :name "list_directory"
     :function (lambda (directory)
                 (mapconcat #'identity
                            (directory-files (expand-file-name directory))
                            "\n"))
     :description "List the contents of a directory"
     :args (list '(:name "directory"
  					   :type string
  					   :description "Path to the directory to list"))
     :category "filesystem")

    ;; List project files
    (gptel-make-tool
     :name "list_project_files"
     :function (lambda ()
                 (if-let ((pr (project-current)))
                     (mapconcat #'identity (project-files pr) "\n")
  				 "No project found for current buffer"))
     :description "List all files in the current project"
     :args (list)
     :category "filesystem")

    ;; Read Emacs documentation
    (gptel-make-tool
     :name "read_documentation"
     :function (lambda (symbol)
                 (let ((sym (intern symbol)))
  				 (cond
                    ((fboundp sym) (documentation sym))
                    ((boundp sym) (documentation-property sym 'variable-documentation))
                    (t (format "No documentation found for %s" symbol)))))
     :description "Read the documentation for a given Emacs function or variable"
     :args (list '(:name "symbol"
  					   :type string
  					   :description "The name of the function or variable to look up"))
     :category "emacs")

    ;; Read URL contents
    (gptel-make-tool
     :name "read_url"
     :function (lambda (url)
                 (with-current-buffer (url-retrieve-synchronously url)
  				 (goto-char (point-min))
  				 (forward-paragraph)
  				 (let ((dom (libxml-parse-html-region (point) (point-max))))
                     (run-at-time 0 nil #'kill-buffer (current-buffer))
                     (with-temp-buffer
  					 (shr-insert-document dom)
  					 (buffer-substring-no-properties (point-min) (point-max))))))
     :description "Fetch and read the contents of a URL"
     :args (list '(:name "url"
  					   :type string
  					   :description "The URL to fetch"))
     :category "web")

    ;; Run shell command (requires confirmation)
    (gptel-make-tool
     :name "run_command"
     :function (lambda (command &optional working_dir)
                 (let ((default-directory (if (and working_dir
  												 (not (string= working_dir "")))
  											(expand-file-name working_dir)
                                            default-directory)))
  				 (shell-command-to-string command)))
     :description "Run a shell command and return its output"
     :args (list '(:name "command"
  					   :type string
  					   :description "The shell command to run")
                 '(:name "working_dir"
  					   :type string
  					   :description "Optional directory to run the command in"))
     :category "command"
     :confirm t
     :include t)

    ;; Append text to buffer
    (gptel-make-tool
     :name "append_to_buffer"
     :function (lambda (buffer text)
                 (with-current-buffer (get-buffer-create buffer)
  				 (save-excursion
                     (goto-char (point-max))
                     (insert text)))
                 (format "Appended text to buffer %s" buffer))
     :description "Append text to an Emacs buffer, creating it if needed"
     :args (list '(:name "buffer"
  					   :type string
  					   :description "The name of the buffer to append to")
                 '(:name "text"
  					   :type string
  					   :description "The text to append"))
     :category "emacs")

    ;; Read PDF contents
    (gptel-make-tool
     :name "read_pdf"
     :function (lambda (filepath)
                 (let ((file (expand-file-name filepath)))
  				 (unless (file-readable-p file)
                     (error "Error: file %s is not readable." file))
  				 (pdf-info-gettext file
                                     (cons 1 (pdf-info-number-of-pages file)))))
     :description "Extract text content from a PDF file"
     :args (list '(:name "filepath"
  					   :type string
  					   :description "Path to the PDF file. Supports relative paths and ~."))
     :category "filesystem")

    ;; Project root, name and branch
    (gptel-make-tool
     :name "project_root"
     :function (lambda ()
                 (if-let ((pr (project-current)))
                     (let* ((root (project-root pr))
                            (default-directory root)
                            (branch (ignore-errors
                                      (car (process-lines-ignore-status
                                            "git" "rev-parse" "--abbrev-ref" "HEAD")))))
                       (format "root: %s\nname: %s\nbranch: %s"
                               root (project-name pr) (or branch "unknown")))
  				 "No project found for current buffer"))
     :description "Return the root directory, name and VC branch of the current project"
     :args (list)
     :category "filesystem")

    ;; Search the project with ripgrep
    (gptel-make-tool
     :name "search_project"
     :function (lambda (pattern &optional glob)
                 (let* ((pr (project-current))
                        (default-directory (if pr (project-root pr) default-directory))
                        (args (append '("--line-number" "--no-heading" "--color" "never"
                                        "--max-count" "20" "--max-columns" "200")
                                      (when (and glob (not (string-empty-p glob)))
                                        (list "--glob" glob))
                                      (list "--regexp" pattern)))
                        (output (with-temp-buffer
  								(let ((status (apply #'call-process "rg" nil t nil args)))
                                    (pcase status
                                      (0 (buffer-string))
                                      (1 "No matches")
                                      (_ (format "ripgrep failed: %s" (buffer-string))))))))
  				 (if (> (length output) 8000)
                       (concat (substring output 0 8000)
                               "\n… output truncated, narrow the search")
                     output)))
     :description "Search the files of the current project with ripgrep, returning matching lines with their file and line number"
     :args (list '(:name "pattern"
  					   :type string
  					   :description "Regular expression to search for")
                 '(:name "glob"
  					   :type string
  					   :optional t
  					   :description "Optional file glob restricting the search, e.g. *.el"))
     :category "project"))
#+end_src

*** Enabling tools

Tools are enabled globally with ~gptel-use-tools~.  To activate them
for a session, open the gptel transient menu with ~C-c g m~ and toggle
the tools you want under the "Tools" section.  You can also require
confirmation before any tool call fires from the same menu.  The
~code~ preset switches on the project-reading set in one step.

*** Available tools

| Tool                | Category   | What it does                                      |
|---------------------+------------+---------------------------------------------------|
| ~read_buffer~       | emacs      | Read the full contents of any live Emacs buffer   |
| ~read_file~         | filesystem | Read a file from disk by path                     |
| ~list_directory~    | filesystem | List files in a directory                         |
| ~list_project_files~| filesystem | List all files in the current project             |
| ~project_root~      | filesystem | Report the project root, name and VC branch       |
| ~search_project~    | project    | ripgrep the project, with an optional file glob   |
| ~read_documentation~| emacs      | Look up docstrings for any Emacs symbol           |
| ~read_url~          | web        | Fetch and render a URL as plain text              |
| ~run_command~       | command    | Run a shell command (always asks for confirmation)|
| ~append_to_buffer~  | emacs      | Append text to a buffer, creating it if needed    |
| ~read_pdf~          | filesystem | Extract text from a PDF via pdf-tools             |

*** Typical workflows

- /Explain this buffer/: open a gptel chat, ask "explain the code in
  buffer foo.el" — the model will call ~read_buffer~ automatically.

- /Project orientation/: from a project chat (~C-c g p~), ask "where is
  the retry logic?" — the model chains ~search_project~ then
  ~read_file~ instead of you pasting anything.

- /PDF Q&A/: with a paper on disk, ask "summarise
  ~/papers/foo.pdf~" — the model calls ~read_pdf~ and summarises
  inline.

- /Documentation lookup/: ask "how does ~consult-ripgrep~ work?" — the
  model calls ~read_documentation~ rather than relying on training
  data, giving you accurate docstrings.

- /Shell tasks/: ask "run the tests for this project" — the model
  constructs the command and prompts you to confirm before running it.

*** Notes

- ~run_command~ has ~:confirm t~, meaning gptel will always show you
  the command and ask before executing it.  Do not remove this.
- ~search_project~ shells out to ~rg~ and caps its output — 20 matches
  per file, 200 columns per line, 8000 characters overall.  A model
  that hits the cap should narrow its pattern, not be given a bigger
  budget.
- ~read_pdf~ requires the ~epdfinfo~ server from pdf-tools to be
  running.  Opening any PDF in Emacs first is sufficient.
- ~list_project_files~ uses ~project.el~ and respects your
  ~.gitignore~ via ~project-vc-extra-root-markers~.
- Tool calls are not free: each round trip resends the conversation so
  far, so a long tool-heavy session is the most expensive thing you can
  do here.  DeepSeek's context caching takes the edge off a repeated
  prefix, but it does not make the resend free.

** Presets
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

A preset bundles a model, system message and tool set under one name.
With a single backend they are no longer about routing cost — they are
about not retyping the same system message.

#+begin_src emacs-lisp
  (with-eval-after-load 'gptel
    ;; Presets landed in gptel 0.9.8; skip them on an older pin rather
    ;; than breaking init.
    (when (fboundp 'gptel-make-preset)

      (gptel-make-preset 'chat
        :description "Plain chat, no tools — the default, made explicit."
        :backend "DeepSeek"
        :model 'deepseek-chat
        :tools nil)

      (gptel-make-preset 'code
        :description "Project-aware coding with the file-reading tools."
        :backend "DeepSeek"
        :model 'deepseek-chat
        :system my-gptel-code-directive
        :tools '("project_root" "list_project_files" "search_project"
                 "read_file" "read_buffer"))

      (gptel-make-preset 'reason
        :description "deepseek-reasoner for hard problems.  No tools."
        :backend "DeepSeek"
        :model 'deepseek-reasoner
        :system my-gptel-code-directive
        :tools nil)

      (gptel-make-preset 'explain
        :description "Explain code to someone who has not seen it."
        :system "Explain what this code does, plainly and concretely.
  Name the moving parts, then walk through the flow.  No filler.")))
#+end_src

| Preset    | What it is                                                  |
|-----------+-------------------------------------------------------------|
| ~chat~    | ~deepseek-chat~, no tools — the default, spelled out         |
| ~code~    | ~deepseek-chat~ with the project-reading tools               |
| ~reason~  | ~deepseek-reasoner~, no tools — slow, for hard problems       |
| ~explain~ | System message only, keeps whatever model is active          |

Apply one from the transient menu (~C-c g m~), or for a single request
write its name as an ~@cookie~ anywhere in the prompt:

#+begin_quote
@code Why does the retry loop in the worker drop the last error?
#+end_quote

The cookie applies only to the final user turn, is offered as a
completion in chat buffers, and leaves your other settings alone.
Presets arrived in gptel 0.9.8, so the whole block is guarded with
~fboundp~ — an older pin from Nix will simply skip it.

** Agentic gptel
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

Two add-ons by gptel's own author turn the chat client into something
that can carry a task on its own:
[[https://github.com/karthink/gptel-agent][gptel-agent]] (file editing,
async Bash, diagnostics, todo lists, sub-agents, skills) and
[[https://github.com/karthink/gptel-preset-collection][gptel-preset-collection]]
(=@include= with completion, =@notify=, =@expand=, =@visible-buffers=).

Both are on MELPA, which means neither is here until Nix puts it on the
load-path — so both blocks are guarded with =locate-library= and simply
do not load otherwise.  *They also need a gptel newer than the latest
stable release*, which is the real gate: the guards elsewhere in this
section (=gptel-make-deepseek=, =gptel-make-preset=) exist because the
pin has historically lagged.  If those guards are firing, these two
packages will not work either.

The point is not to reimplement a terminal coding agent.  It is that
=@gptel-agent do X= works from a Magit buffer, a Dired listing, or a
=*compilation*= window, against whatever is already on screen — and,
over TRAMP, against a remote machine with no Emacs on it.  That is the
part no external CLI agent can reach.

#+begin_src emacs-lisp
  (use-package gptel-preset-collection
    :ensure nil
    :if (locate-library "gptel-preset-collection")
    :after gptel
    :demand t)

  (defvar my-gptel-config-root
    (file-name-directory my/literate-config-file)
    "Root of this configuration repository.
  Deliberately not `user-emacs-directory' — `early-init.el' repoints
  that at `var/', so it names the state directory, not the config.")

  (defun my-gptel-agent-project-dir ()
    "Project root for a new agent session, or `default-directory'.
  With a prefix argument, ask instead."
    (if current-prefix-arg
        (read-directory-name "Agent project: ")
      (if-let ((pr (project-current)))
          (project-root pr)
        default-directory)))

  (defun my-gptel-agent-plan (&optional project-dir)
    "Start a `gptel-agent' session in PROJECT-DIR under the plan preset.
  Plan mode gets read-only filesystem access: it can read, search and
  run diagnostics, but not edit, write or shell out.  This is the one
  to reach for first on an unfamiliar task."
    (interactive (list (my-gptel-agent-project-dir)))
    (gptel-agent project-dir 'gptel-plan))

  (defun my-gptel-check-config ()
    "Check this configuration the way a human would before committing.
  Tangle README.org into a scratch directory, report whether the
  checked-in .el files still match it, then byte-compile the freshly
  tangled `init.el' in a subprocess and return the compiler's output."
    (let* ((root my-gptel-config-root)
           (org (expand-file-name "README.org" root))
           (tmp (make-temp-file "gptel-check-" t))
           (report nil))
      (unless (file-readable-p org)
        (error "No README.org under %s" root))
      (unwind-protect
          (let ((copy (expand-file-name "README.org" tmp)))
            (copy-file org copy t)
            (require 'ob-tangle)
            (org-babel-tangle-file copy)
            (dolist (f '("early-init.el" "init.el"))
              (let ((fresh (expand-file-name f tmp))
                    (live (expand-file-name f root)))
                (push
                 (cond
                  ((not (file-exists-p fresh))
                   (format "%s: README.org no longer tangles it" f))
                  ((not (file-exists-p live))
                   (format "%s: tangled, but missing from the working tree" f))
                  ((eq 0 (call-process "diff" nil nil nil "-q" fresh live))
                   (format "%s: in sync with README.org" f))
                  (t (format "%s: STALE — re-tangle before committing" f)))
                 report)))
            (let ((fresh-init (expand-file-name "init.el" tmp))
                  (emacs (expand-file-name invocation-name invocation-directory)))
              (when (file-exists-p fresh-init)
                (push (with-temp-buffer
                        (call-process emacs nil t nil "--batch"
                                      "-f" "batch-byte-compile" fresh-init)
                        (concat "byte-compile:\n"
                                (if (= (buffer-size) 0)
                                    "  clean"
                                  (buffer-string))))
                      report))))
        (delete-directory tmp t))
      (string-join (nreverse report) "\n")))

  (use-package gptel-agent
    :ensure nil
    :if (locate-library "gptel-agent")
    :after gptel
    :demand t
    :config
    ;; Append rather than set: the default value points at the package's
    ;; own agents/, and dropping it would lose the built-in sub-agents.
    (add-to-list 'gptel-agent-dirs
                 (expand-file-name "agents/" my-gptel-config-root) t)
    ;; Skills need no configuration: `.claude/skills/' is already on
    ;; `gptel-agent-skill-dirs', relative entries are resolved against
    ;; the project root, and relative beats absolute on a name clash.
    (gptel-agent-update)
    :bind
    (("C-c g A" . gptel-agent)
     ("C-c g P" . my-gptel-agent-plan)
     ("C-c g c" . gptel-agent-compact)))

  (with-eval-after-load 'gptel
    (gptel-make-tool
     :name "check_config"
     :function #'my-gptel-check-config
     :description "Verify the Emacs configuration after editing README.org: \
  re-tangles it in a scratch directory, reports whether the checked-in \
  init.el and early-init.el are still in sync, and byte-compiles the \
  result.  Call this after every edit and fix what it reports."
     :args (list)
     :category "project"))
#+end_src

| Keys      | Command                                             |
|-----------+-----------------------------------------------------|
| =C-c g A= | agent session for this project (=C-u= to pick a dir) |
| =C-c g P= | same, but plan mode — read-only filesystem           |
| =C-c g c= | compact the conversation up to point                 |

*** Start in plan mode

=gptel-plan= gets the reading tools and =Diagnostics= but not =Edit=,
=Write= or =Bash=.  Nothing it does can be wrong in a way that costs
anything, which makes it the cheap way to answer the open question:
does DeepSeek actually hold a long tool loop together?  Find that out
before handing it write access.  Two other things to know before you
do:

- =Edit= writes to *disk*, not to buffers.  =global-auto-revert-mode=
  is on, so buffers do refresh — but with =auto-revert-use-notify= nil
  it polls, and auto-revert will not touch a buffer with unsaved
  changes.  Undo for an agent edit is git, not =C-/=.  Commit first.
- Permissions are per-tool, not per-command: =Bash= is =:confirm t= and
  that is the whole model, so =ls= prompts exactly like =rm -rf=.  The
  confirmation is an overlay showing a real diff rather than a
  minibuffer prompt, which helps, but there is no allowlist.  This is
  the one place an ACP client driving OpenCode ([[https://github.com/xenodium/agent-shell][agent-shell]]) is still
  ahead.

*** Self-verification

The lesson from karthink's own write-up: where the agent had a checker
to run, it converged; where it did not, it stalled.  This repository
has no test suite, but it has two things that fail loudly — a tangle
that has drifted, and a byte-compiler.

=check_config= runs both.  It copies README.org to a scratch directory,
tangles it there, diffs the result against the checked-in =.el= files,
then byte-compiles the fresh =init.el= in a subprocess.  It touches
nothing in the working tree.

That staleness check matters more than it looks.  =init.el= is
generated, so an agent that edits README.org and stops has left the
repository in a state where the *old* config is still what boots.  The
byte-compiler will not catch that; a diff will.

Nothing makes the model call it, so =.claude/skills/emacs-config/= says
to — see below.

*** Agents and skills

Sub-agents are Markdown files with YAML frontmatter in
=gptel-agent-dirs=; skills are directories containing a =SKILL.md= in
=gptel-agent-skill-dirs=.  Two live in this repository:

| Path                                  | What it is                             |
|---------------------------------------+----------------------------------------|
| =agents/config-reviewer.md=           | sub-agent: reviews a change to this config |
| =.claude/skills/emacs-config/SKILL.md= | skill: the literate + Nix ground rules |

The skill needs no configuration at all — =.claude/skills/= ships in
the default =gptel-agent-skill-dirs=, relative entries resolve against
the project root, and relative wins over absolute on a name clash.
That is also why it is a skill rather than an addition to
=my-gptel-code-directive=: gptel-agent builds its own system prompt and
does *not* read AGENTS.md, so the conventions have to arrive through a
channel it knows about.  It is loaded on demand, so it costs nothing
until the model asks for it.

*** What this does not replace

=my-gptel-project= and the hand-written tools above still stand.  The
tools are not redundant in practice because presets pick tools by
name — the =code= preset names its own five, =gptel-agent= names its
own — so the two sets never both fire on one request.  Deleting them
would break =code= and =reason= for no gain.

Worth knowing: =gptel-agent-preset= exists to route sub-agent calls to
a cheaper model than the main loop.  With a single backend there is
nothing cheaper to route to, so it is deliberately left at its default.


* Tabspaces
:PROPERTIES:
:header-args:emacs-lisp: :tangle init.el
:END:

Buffer-isolated workspaces on top of =tab-bar= and =project.el=: each
tab keeps its own buffer list, so =C-x b= in the =emacs= tab does not
offer buffers from the =work= tab.

Two things this block deliberately does *not* do:

- It does not redefine =tabspaces-command-map=. The package already
  defines that map — with exactly these bindings — and =fset='s it so
  it can be used as a prefix command. A =defvar= in =:config= runs
  *after* the package is loaded, and =defvar= never reassigns an
  already-bound variable, so the copy was dead code.
- It does not =global-set-key= the prefix. =tabspaces-mode-map= binds
  =tabspaces-keymap-prefix= itself when the mode turns on. The prefix
  is set here in =:custom= (which use-package emits *before* the load,
  which matters — =tabspaces-mode-map= is built at load time from that
  variable, so setting it afterwards would have no effect).

| Keys        | Command                                     |
|-------------+---------------------------------------------|
| =C-c TAB s= | switch to / create workspace                |
| =C-c TAB o= | open or create project + workspace          |
| =C-c TAB b= | switch to a workspace-local buffer          |
| =C-c TAB t= | switch to a buffer and its tab              |
| =C-c TAB r= | remove current buffer from the workspace    |
| =C-c TAB R= | remove a selected buffer from the workspace |
| =C-c TAB C= | clear workspace buffers                     |
| =C-c TAB d= | close workspace, keep buffers               |
| =C-c TAB k= | kill workspace buffers and close it         |
| =C-c TAB w= | show workspaces in the echo area            |
| =C-c TAB T= | toggle the echo-area workspace display      |

The consult integration adds a "Workspace Buffers" source (narrow key
=w=) as the default in =consult-buffer=, and hides the unfiltered
"Buffer" source behind its own =b= narrow key. Candidates are built
with =consult--buffer-pair= to match consult's own buffer sources —
plain buffer names would collide when two workspaces hold same-named
buffers.

#+begin_src emacs-lisp
  (use-package tabspaces
    :ensure nil
    :hook (after-init . tabspaces-mode)
    :custom
    (tabspaces-keymap-prefix "C-c TAB")
    (tabspaces-use-filtered-buffers-as-default t)
    (tabspaces-default-tab "Default")
    (tabspaces-remove-to-default t)
    (tabspaces-include-buffers '("*scratch*"))
    (tabspaces-session t)
    (tabspaces-session-auto-restore t)
    (tabspaces-initialize-project-with-todo nil)
    :config
    (with-eval-after-load 'consult
      (defvar consult-source-workspace
        (list :name     "Workspace Buffers"
              :narrow   ?w
              :category 'buffer
              :face     'consult-buffer
              :history  'buffer-name-history
              :state    #'consult--buffer-state
              :default  t
              :items    (lambda ()
                          (consult--buffer-query
                           :predicate #'tabspaces--local-buffer-p
                           :sort 'visibility
                           :as #'consult--buffer-pair)))
        "Tabspaces-local buffer source for `consult-buffer'.")
      (add-to-list 'consult-buffer-sources 'consult-source-workspace)
      ;; Full buffer list is still reachable via its `b' narrow key.
      (plist-put consult-source-buffer :hidden t)
      (plist-put consult-source-buffer :default nil)))
#+end_src

#+begin_src emacs-lisp
  (defun prot/keyboard-quit-dwim ()
    "Do-What-I-Mean behaviour for `keyboard-quit'."
    (interactive)
    (cond
     ((region-active-p)
      (deactivate-mark))
     ((derived-mode-p 'completion-list-mode)
      (delete-completion-window))
     ((> (minibuffer-depth) 0)
      (abort-recursive-edit))
     (t
      (keyboard-quit))))

  (defun my-project-find-file ()
    "Find file in current project, fallback to consult-find."
    (interactive)
    (if (and (fboundp 'project-current) (project-current))
        (call-interactively #'project-find-file)
      (if (fboundp 'consult-find)
          (consult-find default-directory)
        (call-interactively #'find-file))))

  (defun my-project-find-buffer ()
    "Project-aware buffer switch, fallback to consult-buffer."
    (interactive)
    (if (and (fboundp 'project-current) (project-current))
        (consult-project-buffer)
      (call-interactively #'consult-buffer)))
#+end_src

** Terminal / Compile Keymaps

#+begin_src emacs-lisp
  (defun my-project-eat ()
    "Open eat in current project root with a project-named buffer."
    (interactive)
    (let* ((pr (project-current))
  		 (default-directory (if pr (project-root pr) default-directory))
  		 (name (if pr (project-name pr) "default"))
  		 (buf-name (format "*eat-%s*" name)))
  	(if (get-buffer buf-name)
  		(pop-to-buffer buf-name)
        (eat)
        (rename-buffer buf-name))))

  (defun my-project-compile ()
    "Compile in current project root with a project-named buffer."
    (interactive)
    (let* ((pr (project-current))
  		 (default-directory (if pr (project-root pr) default-directory))
  		 (name (if pr (project-name pr) "default"))
  		 (compilation-buffer-name-function
            (lambda (_mode) (format "*compilation-%s*" name))))
  	(call-interactively #'compile)))

  (defun my-project-sql ()
    "Open SQL interactive in current project."
    (interactive)
    (let ((default-directory (or (and (project-current) (project-root (project-current)))
                                 default-directory)))
      (call-interactively #'sql-connect)))

  (define-key my-term-keymap (kbd "t") #'my-project-eat)
  (define-key my-term-keymap (kbd "c") #'my-project-compile)
  (define-key my-term-keymap (kbd "s") #'my-project-sql)
